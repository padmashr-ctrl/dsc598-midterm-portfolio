02 / Present the case study

A camera that does not just record the world. It changes it.

I studied We Become What We Behold, a five-minute browser game created by Nicky Case. The player frames moments in a crowd; the selected image appears on a central screen and alters how the crowd behaves. Case describes it as a game about “news cycles, vicious cycles, infinite cycles.”

WHAT I LEARNED

The strongest lesson is structural: a game can make its argument through the rule for progress. We Become What We Behold does not only tell me that attention changes behavior; it makes my own clicks produce the cycle. My proposal adapts that principle by making every “verified” memory alter the evidence the player sees next.

GAP 01 / CONTRADICTION

My first draft accepted “everything is CC0.”

The README does say that, but the itch.io page lists the code under the Unlicense. Both are public-domain dedications, so the practical meaning is close, but two primary sources disagree. I now describe both instead of picking one. This changed how I credit my own game: I list every outside asset with its exact licence.

GAP 02 / NEUTRALITY

The first answer treated the player as a neutral photographer.

That missed the causal loop. Published images change the crowd, so selecting is also world-building.

GAP 03 / PROGRESSION

The first answer discussed the message, but not how the game trains the player.

Ordinary scenes are rejected. Progress teaches the player to search for spectacle before the violent ending arrives.

ME / CHALLENGE

You called the camera a neutral point of view, but the hat photograph changes what the crowd does next. Reconsider the camera as part of the system. What does the player cause?

AI / REVISION

The camera is not only observational; it is an editing tool with causal power. Publishing selects a pattern, broadcasts it, and makes the crowd repeat it. The player participates in creating the reality later presented as news.

ME / NEW EVIDENCE

Normal and peaceful photographs are also dismissed as “nothing.” How does that progression rule change the interpretation?

AI / REVISED INSIGHT

The game teaches sensational selection before it condemns the result. Complicity comes from the rule for continuing, not from a final message alone.

TWO RIVAL READINGS I ASKED AI TO COMPARE

A · The game is about the media

The TV is the villain: it twists harmless moments into outrage, and the crowd copies it.

Support: Case’s own tagline names “news cycles.” Headlines change the meaning of each photo.

B · The game is about the player

The TV only shows what I framed. The rule for progress trains me to want spectacle.

Support: Calm photos are dismissed as “nothing,” so the only way forward is to choose conflict.

My verdict: B is better supported by how the game actually plays; A is what it says on the surface. I designed Prove You Remember around B: the system never invents anything on its own. It only extends what the player chose.

MY CONCLUSION + DESIGN DECISION

Hallucination becomes more powerful when the player helps produce it.

A simple “spot the fake image” quiz would keep truth and error separate. My game will instead make each selection update a neighboring tile. The player’s earlier choices become the system’s evidence, so the final memory is partly discovered and partly authored. AI helped name the feedback loop; challenging its neutral-camera assumption led to the mechanic I chose.

04 / Narrative and concept

The system does not lie. It completes what is missing.

My interpretation of Hallucination is a confident completion: when evidence is incomplete, a person or machine fills the gap with something plausible and later forgets which part was inferred.

WORLD

A memory recovery portal

The player enters a clean, bureaucratic website that claims to reconstruct a missing event from damaged snapshots. The interface looks trustworthy because it resembles familiar identity-verification tools.

PLAYER ROLE

The only available witness

The player is asked to verify details from “Event 27.” There is no avatar or backstory to read; identity emerges through the images they choose and reject.

CORE RULE

Selection becomes evidence

Clicking a tile marks it as remembered. The system raises its confidence and quietly mutates nearby images to support that choice. The same action grows less reliable across three stages.

INTENDED EXPERIENCE

Recognition → doubt → responsibility

The opening feels easy, the middle makes the player watch the evidence drift, and the ending asks whether a coherent story is worth certifying when its certainty was manufactured.

“The game is not asking whether memory is true or false. It asks when a guess becomes a fact because an interface repeats it with confidence.”

Reference connection: Nicky Case’s camera loop informed the causal selection mechanic. CAPTCHA interfaces informed the recognizable grid and verification language. I am combining them to make a player question the authority of an interface they already know how to obey.

Stage 1 teaches

A burgundy frame means “remembered,” the counter tracks the goal, and a soft click confirms input.

Stage 2 changes

The same click now affects two tiles. A brief afterimage lets attentive players notice the rewrite.

Stage 3 reconsiders

There is no objectively correct set. The system’s confidence reveals its desire for completion, not truth.

The ending leaves

A personalized mosaic and one question: “Is a complete memory more useful than an honest gap?”

SOUND METHOD

Browser-generated tones

A soft sine click confirms selection; a low hum gains detune as evidence drifts; silence follows the final choice. Sounds will be generated in-browser so the project does not depend on unlicensed files.

Tone.js / official documentation ↗

IMAGERY

Original low-detail vector snapshots: rooms, objects, and thresholds. Each tile must remain readable at phone size and easy to redraw in alternate states.

MOTION

Selected tiles lock in 180 ms. Rewritten neighbors crossfade through a one-frame pink afterimage. Reduced-motion mode swaps instantly and adds a “changed” label.

AUDIO

Sound starts off. The player controls it. Confirmation is tonal and quiet; drift introduces a subtle pitch disagreement; no continuous music is required.

ACCESSIBILITY

Keyboard-selectable tiles, visible focus, live status text, shape-plus-color states, readable contrast, and no essential information communicated by sound alone.

07 / Two-week build plan

Build the feedback loop first. Polish only after it reads clearly.

The minimum successful game is one interaction, three short stages, an opening, and an ending. The schedule protects that core before adding optional sound or extra image sets.

WEEK 2 / PLAYABLE PROTOTYPE

Build

  1. Day 1: Define the 27 tile states and the exact mutation rules on paper.
  2. Day 2: Build the responsive 3×3 grid, keyboard input, selection counter, and reset.
  3. Day 3: Add opening, Stage 1, and transitions between prompts.
  4. Day 4: Add Stage 2 neighbor rewrites and visible afterimages.
  5. Day 5: Add Stage 3, ending receipt, two final choices, and replay.
  6. Weekend: Complete a self-test on phone and laptop; remove any rule that is unclear.

END OF WEEK 2A complete, rough game that can be played from beginning to end without explanation.

WEEK 3 / TEST + REFINE + PUBLISH

Test

  1. Test 1 / comprehension: Can three players explain what changed after Stage 2?
  2. Test 2 / pacing: Do they finish in 5–7 minutes without feeling rushed?
  3. Test 3 / emotion: When do recognition, doubt, and responsibility appear?
  4. Revise: Clarify prompts, timing, focus states, labels, and mutation visibility.
  5. Polish: Add optional generated sound only after the silent version works.
  6. Publish: Check the public URL, phone layout, keyboard path, and restart behavior.

END OF WEEK 3A tested, accessible, published game with documented feedback and intentional revisions.

REQUIRED

27 illustrated tile states, three prompts, neighbor mutation, ending mosaic, replay, keyboard/touch support.

OPTIONAL

Generated tones, a second ending sentence, subtle timer, downloadable memory receipt.

CUT FIRST

Accounts, saved progress, AI image generation, voice input, procedural stories, more than one event.

SUCCESS TEST
